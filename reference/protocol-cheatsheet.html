Codex app-server 集成速查

一页纸的协议与接缝。基线 codex-cli 0.164.0；字段以本机 generate-json-schema 为准，不以本文为准。

配合课程 01 使用 可打印 2026-10-28

01生命周期

一个进程 → 多条 thread → 每条 thread 同时最多一个 turn → 一个 turn 内多次工具调用。 

spawn app-server
  → initialize
  → thread/start | thread/resume
  → turn/start
      ├─ item/agentMessage/delta      (可多次)
      ├─ item/tool/call → 你的结果     (可多次)
      └─ item/started / item/completed
  → turn/completed
  → thread/delete（可选）

turn 结束状态：completed / failed / interrupted。 inProgress 不是结束，忽略它继续等。

02谁在说话

形状方向例子答
{id, method, params} C → S initialize, thread/start, turn/start 是
{id, result} / {id, error} S → C thread/start 的返回 —
{id, method, params} S → C item/tool/call 必须
{method, params} S → C item/agentMessage/delta, turn/completed 否

C = 客户端（宿主），S = app-server。本协议按行分隔 JSON，不带 jsonrpc 字段； id 可以是数字或字符串。有 method + id 是请求， 有 method 无 id 是通知，只有 id 是响应。

03最小会话（JSONL）

→ 客户端发往 app-server← app-server 发回客户端
# 1. 握手：experimentalApi 是 dynamicTools 的前置开关
→ {"id":1,"method":"initialize","params":{
     "clientInfo":{"name":"myapp","version":"0.1.0"},
     "capabilities":{"experimentalApi":true}}}
← {"id":1,"result":{"userAgent":"...","platformFamily":"..."}}

# 2. 建线程：工具只在这里声明，随线程持久化
→ {"id":2,"method":"thread/start","params":{
     "cwd":"/path/to/workspace",
     "sandbox":"read-only",
     "approvalPolicy":"never",
     "ephemeral":false,
     "dynamicTools":[{
       "type":"function",
       "name":"app_get_state",
       "description":"Read the current document.",
       "inputSchema":{"type":"object","properties":{},"additionalProperties":false}
     }]}}
← {"id":2,"result":{"thread":{"id":"th_..."}}}

# 3. 开始一轮
→ {"id":3,"method":"turn/start","params":{
     "threadId":"th_...",
     "input":[{"type":"text","text":"..."}]}}
← {"id":3,"result":{"turn":{"id":"tu_..."}}}

# 4. 文本流（通知，无 id）
← {"method":"item/agentMessage/delta","params":{
     "threadId":"th_...","turnId":"tu_...",
     "itemId":"msg_1","delta":"我先读一下。"}}

# 5. 模型要用手（反向请求，有 id；不回答就永远等）
#    id 由 app-server 分配，首轮常见 0；和客户端请求的 1、2、3 是两个命名空间
← {"method":"item/tool/call","id":0,"params":{
     "threadId":"th_...","turnId":"tu_...",
     "callId":"call_1","namespace":null,
     "tool":"app_get_state","arguments":{}}}

# 6. 宿主回答（原样回传同一个 id；首轮常见 0）
→ {"id":0,"result":{
     "success":true,
     "contentItems":[{"type":"inputText","text":"{\"ok\":true}"}]}}

# 7. 结束
← {"method":"turn/completed","params":{
     "threadId":"th_...",
     "turn":{"id":"tu_...","status":"completed"}}}

05工具结果契约

{
  "success": true | false,
  "contentItems": [
    {"type":"inputText",  "text":"..."},
    {"type":"inputImage",
     "imageUrl":"data:image/png;base64,..."}
  ]
}
  • 失败也是结果：success:false + 可读 JSON，不抛异常给协议层。
  • 图片走 inputImage；文本里删掉 imageUrl，否则 base64 会被重复计费。
  • 工具名 = 模型权限。没声明的工具，它调不到。

06失败码（PaintCodex）

code触发模型该怎么做
revision_conflictexpectedRevision 不匹配，附 currentRevision重读上下文，再决定是否重写
invalid_arguments参数类型 / 形状不合法修正参数后重试
invalid_svgSVG 含脚本、事件、外链或 viewBox 不符重写一个安全、独立的 SVG
layer_not_found / canvas_not_foundid 不存在或不属于当前画布重新读上下文，不要猜 id
top_action_is_user撤销栈顶是用户动作转告用户自己撤销，不代劳
nothing_to_undo撤销栈已空说明没有可撤销的操作
user_declined确认被拒、超时、断线或中断停止该动作，说明原因
render_unavailable / export_unavailable没有连接中的浏览器告知用户先打开画布
tool_timeout工具执行超 30s（人在等待的时间不计）缩小动作，或改成分步

07超时与取消

  • 请求 30s：initialize / thread/* / turn/start。
  • 工具 30s；确认、渲染、导出等人机往返暂停计时。
  • 确认 60s 无答复按拒绝处理；SSE 断开或 turn 中断立即结算。
  • SSE 关闭 → AbortSignal → turn/interrupt + 取消挂起确认。
  • 进程崩溃 → 所有 pending 请求失败、内存 thread 映射清空；下一次对话懒重启。

08升级检查清单

  1. codex --version，确认不低于 0.164.0。
  2. pnpm --filter @paintcodex/daemon codex:protocol-schema 重新生成（输出到 gitignore 目录）。
  3. 与 runtime/protocol.ts 逐字段比对，先改协议类型。
  4. 跑 pnpm -r test，重点看 fake runtime 与工具回归。
  5. 手工冒烟：画一笔 → 让 AI 改 → 删除并确认 → 导出 PNG。
  6. 最后才抬 MINIMUM_CODEX_VERSION。

09把领域换掉时，保留什么

保留：进程 / 线程 / 轮次的状态机；反向工具请求；失败即结果；串行队列；版本闸门；SSE 取消语义。

替换：工具名与 JSON Schema；PromptContext；领域写入用的 dispatcher；哪些动作需要确认；工具结果里的业务字段。
