课程与参考卡里反复出现的词，统一在这里定义。英文名保留，方便你去上游文档里搜。

25 条 随课程增补 基线 codex-cli 0.164.0

A协议与运行时

app-servercodex app-server
Codex CLI 的子命令，启动一个长驻进程，用按行分隔的 JSON 消息与宿主通信。 它负责模型连接、thread 与 turn；宿主负责执行工具。协议目前带 [experimental] 标记。
JSONL 传输line-delimited JSON
一行一个 JSON 对象，stdin 写、stdout 读。没有长度前缀，也不能把一条消息拆成多行再拼。 stderr 是日志，不是协议。本协议的消息不带 jsonrpc 字段。
握手initialize
进程启动后的第一个请求：报上 clientInfo，并声明 capabilities.experimentalApi。 后者是使用 dynamicTools 的前置开关；缺了它，thread/start 会被拒。
线程thread
一段持久对话，也是模型侧的记忆容器。工具在 thread/start 时声明，随线程持久化。 PaintCodex 一条画布一条 thread；删除 thread 就丢掉指代记忆，但不影响画布数据。
轮次turn
一条用户消息引发的工作，可包含多次工具调用。同一 thread 同时最多一个活动 turn。 结束状态是 completed、failed 或 interrupted。
条目item
轮次内的事件单位：助手消息、dynamic tool 调用、命令执行等。 通过 item/started / item/completed 观察；条目也有自己的 id。
通知notification
服务端单向发出、没有 id、不需要回答的消息，例如 item/agentMessage/delta 与 turn/completed。 有 method 但没有 id，就是通知。
反向请求server request
app-server 发给宿主的请求，带 id，必须回答。当前主要就是 item/tool/call。这个 id 由 app-server 分配（首轮常见 0），与客户端请求的 1、2、3 是两个命名空间；响应时原样回传。不回答，模型会一直等；答错，它会基于错的事实继续。
动态工具dynamic tool
宿主在 thread/start 时声明给模型的函数：name、 description、inputSchema。模型只能调用声明过的工具； 声明之外，它没有别的权限。 避免：插件、技能、MCP 工具（它们不是同一个机制）
工具调用tool call
模型请求执行一个工具，携带 tool、arguments 与 callId。callId 把这次调用与后续 item/completed 里的条目对应起来。
工具结果tool result
宿主对工具调用的回答：success 加 contentItems。 失败也是结果：success:false 加一段模型可读的 JSON。 避免：异常、报错弹窗（模型看不见 UI）
内容项contentItems
工具结果的内容数组：inputText（文本）、inputImage（图片 URL，通常是 data URL）、inputAudio。图片必须走 inputImage，不要塞进文本。
恢复线程thread/resume
用持久化的 thread id 从磁盘恢复对话。ephemeral:false 是前提； PaintCodex 把 id 存在 canvases.codexThreadId，daemon 重启后先 resume， 失败则新建并提示“会话已重置”。
中断turn/interrupt
请求停止某条 thread 上正在跑的 turn。宿主不必等 turn/completed 才释放等待： 它会先取消挂起的确认与浏览器往返，再发中断请求。

B宿主与领域

运行时Codex Runtime
daemon 里唯一说 Codex 协议的组件：进程启停、JSON-RPC 收发、thread/turn 状态、事件映射、 版本闸门。它不知道“画布”是什么，只知道工具名与结果。
命令分发器CommandDispatcher
所有画布变更的唯一入口：dispatch(canvasId, { actor, expectedRevision, action })。 人类与 AI 走同一个状态机，区别只在 actor。
执行者actor
user 或 agent。REST 写入永远是 user， 请求体里自带别的 actor 会被拒；agent 只出现在进程内工具执行器里。 “同权”不等于“代权”：AI 只能撤销自己造成的那一步。
版本号revision
画布状态的整数版本，每次变更 +1，用于乐观并发控制。它是“写到哪个版本”，不是撤销历史。 避免：版本、快照编号
期望版本expectedRevision
写操作携带的“我上次看到的 revision”。不匹配就返回 revision_conflict 与 currentRevision，让模型重读；不传则退化为“用刚读到的版本写”。
快照snapshot
某一时刻完整的 CanvasDocument，用于 Undo/Redo，保留最近 20 个。 撤销恢复快照并抬 revision，但不再追加新快照。
SSEServer-Sent Events
daemon 到浏览器的单向流。画布同步只发“变了”的信号，客户端再取完整快照； AI 对话流则逐帧发 delta、tool、confirm、done 等。
确认通道confirmation channel
daemon 自有的“危险动作先问人”机制：SSE 发 confirm，浏览器 POST /paint/ai/confirm 回答，挂起的工具继续或返回 user_declined。 60 秒无答复视为拒绝。它不是 Codex 的 approval policy。
线程存储thread store
canvasId → threadId 的持久映射。daemon 重启后靠它找回对话； 没有它，thread 只活在内存里，进程一退记忆就没了。
版本闸门version gate
daemon 启动时跑 codex --version，低于 0.164.0 就不注册 AI 路由， 由 /health 给出可操作的原因。它挡的是“第一次对话才炸”，不是安全边界。
懒重启lazy restart
app-server 崩溃后，当前 turn 失败、内存映射清空，但不在崩溃回调里立刻拉起； 下一次 startTurn 才重新 spawn 与 initialize。 代价是崩溃后的下一句话才恢复，收益是不会形成重启风暴。

用词约定

统一
课程里说“线程”就是 thread，“轮次”就是 turn，“条目”就是 item；不混用“会话”“请求”“事件”。
保留英文
协议字段、方法名、状态值保留英文原文，方便直接搜上游 README 与 issue。
避免
“AI 自己操作画布”——准确说法是“模型请求工具，宿主执行后改画布”。
