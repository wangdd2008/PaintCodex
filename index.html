01课程

每一课只解决一个可验证的小问题；学完一课，你应该能用自己的话讲清它，并在代码里指出来。 课程 02 起是动手环节。

  1. 一条消息的旅程 从 exec 到 app-server：四个名词、五道接缝、一条真实消息流。
  2. 亲手跑通一次会话 运行一个最小脚本：建线程、声明 notes_add、回答一次 item/tool/call，再给它加字段。
  3. 给模型装手 工具 schema、失败语义、expectedRevision、串行队列——什么该暴露，什么不该。
  4. 把 turn 接到浏览器 SSE 帧、确认通道、浏览器往返（渲染预览、导出）与取消语义。
  5. 会话与故障 thread 持久化、懒重启、版本闸门、协议漂移；升级 codex 时先看哪里。
  6. 迁移演练 为你的 Web 应用设计工具集，并写一个能跑的最小垂直切片。

03它为什么值得学

大多数「AI 集成」停在文本：模型回一段话，产品再自己解析。那等于让模型隔着一层玻璃指挥， 它看不见结果，也没法多步修正。dynamic tools 把玻璃拿掉：模型请求一个已声明的函数， 宿主在进程内执行，把结构化结果送回模型。于是「读 → 改 → 复核 → 再改」才成立。

代价是你得自己维护一条会话状态机：进程、线程、轮次、请求 id、超时、取消、确认、崩溃恢复。 这六课就是这条状态机的拆解。

一句话

模型没有手。手是你在建线程时声明的工具；集成工作的大半，是维护「调用 → 执行 → 结果」这条回路。
