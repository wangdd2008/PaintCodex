# UI Visual Polish — 快赢 1–5（高级感第一阶段）

Status: ready-for-agent

## Problem Statement

PaintCodex 的界面已经是一套纪律良好的「真黑平面」系统，但停在工程工具的标准线，与专业创作工具（Figma / Procreate 一类）的气质仍有差距。评审（frontend-design 视角）定位到五个低成本、低风险的视觉改进点，统称「快赢 1–5」：

1. 卡片圆角 20px 偏软偏「糖」，与专业工具的锐利气质冲突。
2. 中文字号阶梯（20/16/14/12）偏保守，标题与正文层级差不足，中文标题无专门字距。
3. 画布库卡片 meta 用 `·` 分隔串（如 `1920×1080·3层`），读起来是模板化 chrome。
4. 画布空态（无画布 / 加载失败等）用虚线边框 + 文字，有「临时占位」感。
5. 画布库卡片 hover 只有 `translateY(-1px)` 微位移，反馈弱且常见。

这些不改变功能语义、不改布局骨架、不引入新依赖，目标是让界面更「高级」而不是更「花哨」。

## Solution

对设计 token 与两个视图（画布库、画布空态）做一轮克制的视觉精修：

1. **圆角收紧**：卡片/面板圆角从 20px 收到 12px，嵌套小件相应递减；按钮与胶囊保留全圆角（pill）。整个界面从「圆润」转为「锐利克制」。
2. **标题排版**：全局标题字号 20px → 22px；中文标题字距收紧到 -0.02em；正文/辅助层级拉开，中文阅读更稳。
3. **库卡片 meta 分层**：`尺寸×层数` 与 `相对时间` 从一行 `·` 分隔改为两个独立行（或清晰分组），去掉中间点分隔符；文本内容（尺寸、N 层、时间）保持不变。
4. **空态质感**：虚线边框改为实色底 + 细点阵/网格底纹，保留所有文案与按钮锚点，让空态像「待产出的作品」而不是「临时占位」。
5. **库卡片 hover**：hover 反馈从位移改为边框高亮 + 缩略图轻微放大（保留键盘 focus 样式）。

改完后的验收标准：三个视图（画布工作区、画布库、监控）肉眼可辨更克制、更专业；全部行为测试保持绿色；键盘可用性与可访问性不退化。

## User Stories

1. As a 画师用户, I want 画布工作区的卡片圆角更锐利, so that 界面气质更像专业创作工具而不是普通后台面板。
2. As a 画师用户, I want 面板/卡片与按钮/胶囊的圆角层级更分明, so that 我一眼能区分「容器」与「控件」。
3. As a 画师用户, I want 界面标题更大、层级差更明显, so that 中文长标题也读得清、压得住页面。
4. As a 画师用户, I want 中文标题的字距经过专门调整, so that 标题不显得松散、更像排版过的成品。
5. As a 画师用户, I want 画布库卡片把「尺寸×层数」和「更新时间」分开呈现, so that 我不必从一行 `·` 分隔串里拆读信息。
6. As a 画师用户, I want 画布库卡片 hover 时有明确的边框/内容反馈, so that 我清楚知道指针落在哪张画布上。
7. As a 画师用户, I want 画布库卡片在键盘聚焦时同样有清晰反馈, so that 无障碍用户不会丢失定位。
8. As a 画师用户, I want 无画布空态不再是一块虚线框, so that 我第一次打开应用时感到它「值得开始画」，而不是「还没做完」。
9. As a 画师用户, I want 空态的点阵底纹保持低调不干扰文字, so that 引导文案与主操作依然一眼可见。
10. As a 画师用户, I want 空态的所有文案与按钮（还没有画布 / 开始一张画布 / 重试 / 新建画布）保持原样, so that 我不会因为改视觉而失去熟悉的入口。
11. As a 画师用户, I want 监控页的统计卡片继承新的圆角 token, so that 整个应用的视觉语言保持一致。
12. As a 开发者, I want 这些改动全部落在现有 CSS token 与组件上, so that 不引入新依赖、不改变布局骨架、不重写组件。
13. As a 开发者, I want 全部现有行为测试保持绿色, so that 视觉精修不会悄悄破坏功能语义。
14. As a 开发者, I want 库卡片 meta 的文本断言（尺寸 / N 层 / 时间）不被改动破坏, so that 测试锚点稳定。
15. As a 开发者, I want 空态的 `.canvas-gate` 类名与文案按钮保留, so that 空态相关测试无需重写。

## Implementation Decisions

### 1. 圆角阶梯收紧（token 层）

设计系统当前圆角阶梯为 20 / 12 / 8 / 999（卡片、面板 → 小件 → 标签 → 全圆角控件）。改为 12 / 8 / 6 / 999：

- `--radius-card` 与 `--radius-panel`：20px → 12px（卡片、面板、工具条、图层列、对话列、库卡片）。
- `--radius-small`：12px → 8px（输入框、错误条、确认条、浮层、宽度选择器）。
- `--radius-chip`：8px → 6px（内嵌小标签、输入框内的标签）。
- `--radius-control` 保持 999px（按钮、胶囊、拖拽条、折叠把手）。

凡引用这些 token 的组件（含监控页统计卡片、工具条、折叠把手）自动继承新圆角；不逐处改组件的局部数值。任何组件里写死的圆角值（如消息气泡 18px、canvas-frame 8px）保持不动，除非评审确认其为「容器圆角」。

### 2. 标题排版（token 层）

- `--fs-title`：20px → 22px（页面标题、空态标题）。
- `--fs-kpi`（24px）、`--fs-section`（16px）、`--fs-body`（14px）、`--fs-small`（12px）保持不变，拉开标题与正文的层级差。
- 标题字距：`letter-spacing` 从 -0.01em 收紧到 -0.02em（仅标题类元素；正文保持 0）。
- 标题字重保持 600，行高维持现状；不引入新字体文件（中文字体仍走系统字体回退）。

### 3. 库卡片 meta 分层（DOM 微调）

- `CanvasLibraryPage` 卡片体的 meta 区从「一行 `·` 分隔」改为两行结构：第一行 `尺寸 × 层数`，第二行相对更新时间。
- 文本内容不变：仍渲染 `1280 × 720`、`0 层`、`分钟前/小时前/天前/刚刚`，保证现有文本断言成立。
- 视觉上时间行降一级明度（用现有 muted/faint token），强化「信息分层」而不是「装饰」。

### 4. 空态质感（CSS 层，DOM 结构不变）

- `.canvas-gate` 的虚线边框改为实色底：保留 `#080808` 工作井底色，用细点阵（或极淡网格）底纹代替虚线框，底纹透明度控制在不妨碍文字的区间。
- 保留 `.canvas-gate` 类名、`canvas-gate__title/description/reason/actions` 结构以及全部文案与按钮（还没有画布 / 开始一张画布 / 重试 / 新建画布）。
- 空态主操作（反白按钮）与其他态保持一致，不加新装饰。

### 5. 库卡片 hover（CSS 层）

- `.canvas-card` hover：去掉 `translateY(-1px)` 位移，改为边框高亮（现有 hover 边框色 `#2e2e2e` 提亮一级）+ 缩略图 `img` 轻微放大（约 1.02 倍，`overflow: hidden` 已存在，无需改结构）。
- `focus-visible` 保留现有 outline 样式；hover 与 focus 的反馈强度一致，不互相覆盖。

### 6. 测试接缝（seams）

- **最高可用接缝**：现有行为测试套件。改动全部落在渲染层，功能语义不变，因此对 `apps/web/test` 现有测试应透明。
- **文本锚点接缝**：`canvas-library` 测试对 `1280 × 720`、`0 层`、相对时间的存在性断言；`canvas-gate` 测试对 `还没有画布`、`开始一张画布`、`.canvas-gate` 类名与按钮的断言。实现时保留这些锚点即可无改测试。
- **视觉验收接缝**：项目当前无截图自动化测试；以 dev server + 浏览器截图人工对比三视图（画布工作区、画布库、监控）作为验收手段。

## Testing Decisions

- 只测外部可观察行为，不测实现细节：本次改动主要是视觉，因此测试目标不是「某个类名带新值」，而是「功能语义与可访问锚点不回归」。
- 应保持全绿的模块：`apps/web` 全部测试（重点是 canvas-library、canvas-gate、layer-panel、app-route、narrow-viewport）。
- 需要人工验收的部分：三视图截图对比（圆角、标题字号、库卡片 meta 分层、空态底纹、hover 反馈）；键盘 Tab 遍历库卡片与空态按钮，确认 focus 可见。
- 先例：项目现有测试均为行为断言（React Testing Library + jsdom），无视觉快照测试；本次沿用该模式，不引入新的测试框架。

## Out of Scope

- 布局一体化（工具条+侧栏连体、1px 分隔重构）—— 属于结构性升级，另行评估。
- 色彩分工决策（酸绿降频 / AI 橙与系统绿的分工 / 更换 accent）—— 需用户拍板品牌方向。
- 入场动效与操作反馈动画编排。
- 引入新的中文字体文件或可变字体。
- 库卡片缩略图生成、重命名交互、删除确认等已有行为的改动。
- 监控页布局或信息架构调整（仅随圆角 token 自动继承）。
- 浅色模式 / 主题切换。

## Further Notes

- 快赢 1 的圆角 token 改动会传导到监控页统计卡片、工具条、折叠把手等所有引用 token 的组件；验收时一并检查监控页，避免遗漏视觉语言不一致。
- 与既有 spec 的边界：`workspace-layout-and-zoom`（布局与缩放）不重叠；`monitor-readability`（监控可读性）不重叠；本次仅做 token 与两视图的精修。
- 若未来实施结构性升级（布局一体化），本 spec 的 token 结论（圆角 12px、标题 22px）应作为其基线，避免重复返工。
- 术语遵循 GLOSSARY：画布文档、画布库、无画布（No Canvas）、空画布（Empty Canvas）、保存状态等。
