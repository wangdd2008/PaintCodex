# PaintCodex Phase 1 产品体验审计（统一报告）

**Status:** 待决策 / 可进入排期  
**日期:** 2026-10-26  
**审计方式:** 4 个 product-manager 子智能体并行审计 + 主 agent 真实浏览器走查  
**现场环境:** Web `localhost:5173`，Daemon `127.0.0.1:3210`，Codex CLI 0.164.0，默认视口 1264×625  
**范围:** 首次进入、画布与画笔、图层与选择、AI 对话、监控、导出与持久化、响应式、可访问性、本地化、保存/连接/错误反馈  
**约束:** 不新增大的板块功能；只完善现有能力。Phase 1 明确排除项不重开。

---

## 0. 结论先行

Phase 1 已经能完成「建画布 → 画 → 刷新 → 导出」，服务端持久化、撤销/重做、多标签同步、AI 生成图层、监控 trace 都经过现场验证。真正拖累体验的不是功能少，而是**三个错误信号**：

1. **没有画布时，画布看起来能画，笔画却静默消失。**
2. **每 30 秒自动下载一次 JSON，把“导出”伪装成“保存”；真正的保存状态反而不可见。**
3. **状态栏写“缩放 100%”，实际显示约 44.8%；监控又同时显示“错误率 0.0%”和“1 个错误”。**

这三类问题共同指向一个产品原则：**系统状态必须诚实、可见、可行动**。本轮不需要新模块，只需要把已有的保存、连接、选中、缩放、错误、操作结果如实呈现出来，再把图层和画笔的现有能力补完整。

**建议先做 3 个 P0，再做 17 个 P1；P2 在本轮末收口。** 预计 8–10 个工程日（单人，含测试；不含用户访谈与真机验证）。

## 3. P0 详情

### UX-01 无画布时画布仍可交互，笔画静默丢弃

**现场**

- 无 `canvasId`、无 localStorage 时，画布区已渲染一张 1920×1080 白画布，画笔可点。
- 拖一条线，800ms 后：`layers:0`、`nonWhitePixels:0`、`error:null`、`undoDisabled:true`。
- `CanvasStage.handlePathCreated` 在 `!current` 时直接 `canvas.remove(path)`，没有提示。
- AI 输入框同样可用，AI 会主动建议“在画布上添加图层”，但没有承载对象。

**为什么是 P0**

任何首次用户只要先画一笔就会触发；用户会认为“浏览器/触控/应用不支持画图”，而不是“还没建画布”。这是确定性的第一会话流失点。

**建议**

1. 无画布时 `isDrawingMode=false`，画笔/选择禁用；`handlePathCreated` 保留防御性 guard。
2. 画布区覆盖空状态层或至少 `pointer-events:none`，不要渲染“看起来能画”的假画布。
3. 在画布区放唯一主 CTA「新建画布」，图层面板文案改为「还没有画布，先新建一张」。
4. 无画布时 AI 输入框禁用并说明原因；不要允许 AI 空承诺。
5. 加载失败/daemon 离线与“无画布”区分，提供重试与新建入口。

**验收**

- Given 无画布，when 点击画笔或画布，then 画笔 disabled、不产生路径、不发图层 POST。
- Given 无画布，then 画布区有主 CTA，AI 输入框 disabled。
- Given 有画布，when 画第一笔，then 正常创建 `Stroke 1`。
- Given daemon 离线，then 显示可操作错误，而不是可交互白画布。

**来源:** `01-onboarding-canvas.md` F-01

### UX-02 停止假保存，建立真实保存/失败反馈

**现场**

- `App.tsx` 每 30 秒调用 `downloadCanvasJson`；新建画布空闲 33 秒后拦截到 1 次 `Untitled.json` 下载。
- 没有“保存中/已保存/失败”状态；`saving` 只禁用撤销、重做、删除。
- 保存失败只显示顶栏 12px 红字；`CanvasStage` 的 catch 会 `canvas.remove(path)`，笔画直接消失。
- 服务端每次 mutation 都持久化，刷新与多标签同步验证通过；自动下载不承担保存职责。

**为什么是 P0**

它同时制造了“保存了”和“没保存”两种错误认知：自动下载让用户以为保存了，但文件不可恢复；真正失败时笔画消失，用户不知道发生了什么。这是信任问题，不是文案问题。

**建议**

1. **删除 30 秒自动下载 effect。** 手动导出保留为显式备份。
2. 状态栏建立唯一保存状态：`保存中…` / `已保存 · 刚刚` / `已保存 · 12 秒前` / `保存失败 · 重试`；连续笔画用 ≤500ms 防抖。
3. 保存失败**不要立即移除笔画**；保留并标记“未保存/待重试”，提供重试。若工程上不可行，至少明确提示“这一笔未保存”。
4. 画布级错误改为画布区顶部 `role="alert"` 横幅，含原因与重试；顶栏不再承载主要错误。
5. 操作结果统一为“一行状态 + 撤销”，见 UX-12/AI-02；撤销必须绑定 revision，避免撤错对象。

**验收**

- 新建画布空闲 30 分钟，下载次数 0。
- 画一笔后 ≤1 秒显示「已保存」；连续 5 笔不闪烁。
- 停 daemon 画一笔：≤2 秒出现中文错误与「重试」；笔画不被静默移除或明确显示未保存。
- 删除/AI 生成/导出都有可见结果反馈，同一时刻最多一条，不遮挡画布中心。

**来源:** `01-onboarding-canvas.md` F-03/F-09；`04-cross-cutting.md` CC-01

### UX-03 监控错误率与错误数口径矛盾

**现场**

- 5 分钟窗口：`错误率 0.0%`，hint `1 个错误`。
- `repository.stats()`：`errorCount` 统计所有分类的 `level='error'`；`errorRate = httpFailureCount / requestCount`，只统计 HTTP 的 warn/error。
- `ratio(0,0)` 返回 `0`，所以没有 HTTP 请求也显示 `0.0%`。

**为什么是 P0（监控域）**

监控是唯一可观测界面。数字自相矛盾会让开发者得出“没有错误”的结论，直接影响对 AI 失败、Codex 超时、画布冲突的判断。它不一定阻塞绘画，但会摧毁排障信任。

**建议**

1. 卡片改名「HTTP 错误率」，hint 写 `0 失败 / 24 请求`，分子分母都可见。
2. 单独呈现全部错误：`全部错误 1 · ai-chat 1`，复用分类条错误计数。
3. 分母为 0 显示 `—`，不显示 `0.0%`。
4. 若产品希望“错误率”指全部日志，则改公式并同步文案；本轮建议保留 HTTP 口径，因为分母明确。

**验收**

- 1 个 ai-chat error、0 个 HTTP 失败时，不再出现无解释的“0.0% / 1 个错误”。
- 0 个 HTTP 请求时显示 `—`。
- hint 数字可复算，分类条错误计数与“全部错误”一致。

**来源:** `03-ai-monitor.md` MON-01

## 4. P1 详情

### UX-04 首次进入主 CTA 与 AI 空承诺

- **现场:** 唯一入口是右上角「新建画布」；图层面板写「尚未加载画布。」；画布提示为英文 `Blank 1920 × 1080 canvas`；无画布时 AI 回复“想聊天，还是让我在画布上添加一层新的矢量图形？”。
- **建议:** 画布区放唯一主 CTA「开始一张画布」+ 一句“1920×1080，画完可以让 AI 添加图层”；图层面板改「还没有画布」；无画布时 AI 禁用并显示原因；加载失败提供重试/新建。
- **验收:** 无画布时画布区有可键盘聚焦的主按钮；AI disabled；首次页面不出现 `Blank`/`Untitled`；加载失败不显示可交互白画布。
- **来源:** F-02 + AI-04

### UX-05 新建画布不丢旧画布入口

- **现场:** 新建无确认；`replaceState` 覆盖 URL 与 localStorage；`history.back()` 离开应用；旧画布仍在 SQLite，但 UI 不可达。
- **建议:** 有画布时新建先确认；提供“返回上一张画布”（`previousCanvasId` 或 `pushState + popstate`，二选一）；新建失败不覆盖旧 id；不做画布列表。
- **验收:** 取消后 URL/localStorage 不变；确认新建后可一次操作返回旧画布且图层完整；失败后当前画布仍可用。
- **来源:** F-04

### UX-06 画布身份与导出文件名

- **现场:** 所有画布/导出都叫 `Untitled`；名称是 `<span>`，无编辑入口；`POST /paint/canvas` 支持 `name` 但前端没传；无 `PATCH /paint/canvas/:id`。
- **建议:** 先做快速缓解：默认名 `未命名 2026-10-26 14:32`，导出带时间戳；再做完整重命名（inline edit + PATCH 仅更新 name）。两张同名画布导出时用时间戳/短 id 区分。
- **验收:** 新建不是裸 `Untitled`；改名后菜单栏、导出、刷新都使用新名；请求失败回滚；键盘可进入编辑。
- **来源:** F-05

### UX-07 图层命名唯一

- **现场:** 删除 `Stroke 4` 后再画，列表出现两个 `Stroke 8`；命名用 `layers.length + 1`。
- **建议:** 用现有 `Stroke N` 的最大编号 + 1，或画布级递增计数器；不要为此加数据库字段；不自动改已有重名（避免静默改用户数据）。
- **验收:** 8 层删 4 再画 → `Stroke 9`；刷新后继续下一个未占用编号；删除确认与读屏能区分。
- **来源:** F-06 + L-05

### UX-08 状态栏真实缩放与信息去重

- **现场:** 实际显示 44.8%，状态栏硬编码 `缩放: 100%`；名称/尺寸在菜单栏、画布 hint、状态栏重复。
- **建议:** 用 `canvasScreen.width / canvas.width` 计算真实比例，窗口变化实时更新；本轮不做缩放控件，措辞用「适应窗口 45%」；状态栏只保留尺寸、真实比例、工具、保存状态；移除重复 hint。
- **验收:** 1264×625 显示 44.8% ±1%；调整窗口实时更新；代码无硬编码 100%；状态栏每格都能回答一个问题。
- **来源:** F-07 + F-10

### UX-09 图层“当前”语义与键盘可达

- **现场:** `activeLayerId` 只用于面板高亮，`CanvasStage` 不读；点击 AI 图层行不会选中画布对象，点击笔迹行画布无反馈；行 `tabIndex=-1`、无 role，键盘只能到可见性/删除。
- **建议:** 先定义 active 的唯一含义（建议“选中/定位”，不是“绘制目标”）：AI 图层点击后设为 Fabric activeObject，笔迹图层短时高亮；行改为可聚焦控件（button 或 listbox+option），↑/↓ 移动、Enter/Space 选中、Home/End 首尾；补 `:focus-visible`。若不做任何行为，则去掉整行点击与 `cursor:pointer`，诚实降级。
- **验收:** 点击 AI 行出现变换框并可拖动；点击笔迹行 800ms 高亮后恢复；键盘可完成图层选择/隐藏/显示/删除/撤销；读屏播报名称、类型、可见性、选中态。
- **来源:** L-03 + L-01 + CC-05

### UX-10 图层命中区与可见性语义

- **现场:** 可见性 7×11 px、删除 16×16 px；`aria-label` 是动作，`aria-pressed` 是状态，读屏出现“显示 Stroke 1，未按下”。
- **建议:** 命中区 ≥24×24（可见性建议 28×28），间距 ≥4px；行高 36–40px，靠热区扩展而不是放大字形；可见性标签固定为「{name} 可见性」+ `aria-pressed` 表示是否可见，或只用状态标签；图标改眼睛/斜线或保留圆点但 hover/focus 显示文字。
- **验收:** 所有图层按钮 ≥24×24；200% 缩放不裁切；读屏不出现动作/状态矛盾；8 层时图层面板 ≤300px（依赖 UX-11）。
- **来源:** L-02 + L-09 + CC-02

### UX-11 图层增长不挤压 AI 对话

- **现场:** 8 层：侧栏 595 > 556.75，聊天区 467 → 186.75，底部 600.75 逼近工作区底部约 597；侧栏整体滚动。
- **建议:** 最小方案 A：侧栏 `overflow:hidden`；图层面板 `max-height:300px` + 图层列表独立滚动；AI 面板 `flex:1; min-height:240px`；新图层自动 `scrollIntoView({block:'nearest'})`。不做折叠/分隔条（后续）。
- **验收:** 8 层聊天区 ≥240px，输入框与发送完整可见；20 层侧栏无整体滚动；新图层自动进入可视区。
- **来源:** L-07

### UX-12 删除后恢复条

- **现场:** `window.confirm` 原生弹窗；删除后无 toast/撤销入口；补测确认删除可撤销（9→8→9）。
- **建议:** 去掉原生 confirm，改为直接删除 + 图层面板顶部 5–8 秒恢复条「已删除「Stroke 4」· 撤销」，复用现有 `undo()`；同一时间只保留最近一条；失败就地显示重试。保留工具栏撤销作为兜底。
- **验收:** 删除后 1 个往返内消失并出现恢复条；点撤销后名称、可见性、内容、像素完全恢复；连续删除只显示最近一条；失败不出现“看起来删掉了但刷新又回来”。
- **来源:** L-06

### UX-13 图层名称/透明度/类型中文化

- **现场:** 协议与渲染已支持 `name`、`opacity`；UI 只有可见性和删除；类型显示 `vector`。
- **建议:** 行内重命名（双击或小按钮，Enter/失焦提交，Esc 取消，空值回退）；透明度滑块 0–100%（拖动只本地预览，松手 `change` 才 PATCH，保证一次拖动=一个撤销步）；类型中文化为「笔迹」/「AI」/「图片」；不改 `zIndex`（协议不支持，spec 列为 Phase 2）。
- **验收:** 改名后列表、刷新、导出 JSON 都是新名；Esc 不产生 PATCH；透明度 40% 后撤销一次回到拖动前；不出现英文 `vector`。
- **来源:** L-04 + L-10

### UX-14 AI 等待反馈与成功落地确认

- **现场:** 发送到图层出现约 19–20 秒，只有「AI 正在思考…」；完成后 `steps:[]`；后端已发 `layerCreated {id,name}`，前端未消费。
- **建议:** 本地计时显示「已用 12s」；首个 delta 到达切「正在生成…」；完成后保留「已完成 · 用时 19s」；消费 `layerCreated`，在助手气泡下加「已添加图层「AI — 红色圆形」· 撤销上一步」，撤销必须用 revision 守卫，用户之后又画了就降级为纯文本。
- **验收:** 等待有每秒计时；delta 到达文案同步；完成后有终态；成功生成有图层确认；未做新操作时可安全撤销，否则撤销入口不可用。
- **来源:** AI-01 + AI-02

### UX-15 AI 错误可恢复

- **现场:** 错误 `role=alert`；超时映射中文；无重试；发送前清空输入，失败不恢复；`Failed to fetch`/`AI request failed (status)` 是英文；失败留下空助手气泡（代码推导）。
- **建议:** 中文错误分类（daemon 不可达、超时、5xx、canvas_required）；错误条内置「重试」，复用最后一条用户消息和空助手气泡，不追加新消息；失败后输入框为空才恢复草稿；失败气泡标「未完成」；超时文案的“重试”要有按钮承接。
- **验收:** 停 daemon 显示中文可操作错误；重试不产生重复用户消息；草稿按规则恢复；无空气泡；超时“重试”可点。
- **来源:** AI-05

### UX-16 取消不计入 AI 失败，小样本不显示确定百分比

- **现场:** 取消记录 `chat_completed` + `warn + aborted`；成功率只算 `info`；5 分钟窗口内唯一 chat 是取消，显示 0/1 = 0.0%。
- **建议:** 成功率分母剔除 `aborted:true`，单列「取消」计数；`n<5` 显示 `—`，hint 保留 `0/1 chats · 1 取消`；真实失败仍计入分母且不计成功；日志保留 `aborted` 与 warn 供 trace。
- **验收:** 1 成功 + 1 取消 → 100.0%（1/1）且 hint 显示 1 取消；只有取消时不显示 0.0%；5 次成功才显示 100.0%。
- **来源:** AI-03 + MON-02

### UX-17 画布连接状态

- **现场:** SSE 多标签同步正常（1.2 秒 8→9 层）；`onError` 未接入 `App.tsx`；画布页无任何连接指示；监控页已有「实时中/重新连接中…」。
- **建议:** 维护 `connecting | live | reconnecting`；`onOpen → live`，`onError → reconnecting`；状态栏小圆点 + 短文案，复用监控视觉；断线用琥珀色，不用红色错误横幅；恢复后已有 `onOpen → refreshCanvas`，无需轮询；不提供手动重连/离线队列。
- **验收:** 打开 ≤1 秒「连接中…」→「实时中」；停 daemon ≤3 秒「重新连接中…」；恢复 ≤5 秒回「实时中」并自动刷新一次；读屏只播报一次；不新增轮询请求。
- **来源:** CONN-01 + CC-03

### UX-18 窄屏可用（≥360px），不做完整移动端

- **现场:** 390×844：body scrollWidth 440、画布 34×18、侧栏 300、菜单延伸到 x=424；`app.css` 固定 `56px 1fr 300px`，无工作区媒体查询。
- **建议:** 明确承诺「桌面优先、窄屏可用（≥360px）」，不做完整移动端。断点建议：≤1100px 侧栏 `clamp(260px,24vw,320px)`、工具条 48px；≤860px 侧栏改覆盖式抽屉 `min(320px,86vw)`、菜单允许换行、隐藏文档名；≤560px 抽屉接近全宽、导出进第二行、状态栏允许换行；画布最小可用宽度 ≥280px；侧栏分区滚动（UX-11）。不做触控手势/双指缩放/移动端专用工具栏。
- **验收:** 390×844 无横向滚动；画布 ≥340×190；能完成建画布→画→撤销→导出→刷新保留；侧栏可 Esc 关闭且焦点返回；768/1024/1264 无溢出；12 层时 AI 输入框可见。
- **来源:** CC-04

### UX-19 本地化与语言声明

- **现场:** `<html lang="en">`；`Untitled`、`Blank 1920 × 1080 canvas`、`vector`、`AI chat`、`PaintCodex canvas`、`Logs:`、`chats`、`Stroke N`。
- **建议:** `lang="zh-CN"`；默认画布名 `未命名`、导出 `未命名.png/json`；空画布提示 `未创建画布 · 1920 × 1080`；类型 `矢量`；aria-label 中文；监控错误 `日志加载失败：…`；成功率单位 `次对话`；图层名 `笔迹 N`；技术白名单保留：`PaintCodex`、`PNG`、`JSON`、`SVG`、`AI`、`Codex CLI`、`traceId`、`http_request`、`sse_subscribe`、`chat_completed`、分类名。
- **验收:** `lang=zh-CN`；无白名单外英文句子；读屏标签中文；新画布默认名/导出名中文；系统图层名中文；daemon 默认名改动后 API 契约与测试同步。
- **来源:** CC-06

### UX-20 画笔颜色与粗细

- **现场:** 固定 `#111111`、宽度 4；858px 显示下约 1.8px；无颜色/粗细/硬度/预览；AI 可彩色，用户只能细黑线。
- **建议:** 只补两个最小控制：常用色板（黑、深灰、红、橙、蓝、绿）+ 自定义颜色；4 档粗细（2/4/8/16）带预览；默认从 4 调到 6 或 8，让 44.8% 显示下仍可见；设置放会话状态，不要求跨刷新持久化；不做硬度/压感/纹理。
- **验收:** 选红色/8 后新笔画使用新设置，已有图层不变；刷新回默认可接受；色板与粗细可 Tab 聚焦、有 aria-label、不只靠颜色传达状态；默认屏幕笔宽 ≥3px。
- **来源:** F-08

## 6. 已验证可用（不要重做）

以下能力现场验证通过，本轮不要为了“优化”而重写：

- 新建画布 → 画线 → 刷新，图层与笔迹保留。
- AI 生成图层 → 刷新，图层保留；AI 选择工具可移动/缩放 AI 图层（源码路径）。
- `Ctrl+Z`、`Ctrl+Y`、`Ctrl+Shift+Z` 可用；输入框聚焦时不会拦截。
- 隐藏图层后撤销恢复可见性；删除图层后撤销完整恢复（9→8→9 补测）。
- 多标签同 `canvasId` 同步：B 页画一笔，A 页 1.2 秒内 8→9 层。
- 有画布时 PNG/JSON 导出能产生文件；PNG 内部尺寸 1920×1080。
- 服务端逐次 mutation 持久化；刷新恢复 `canvasId`、图层、修订。
- 监控页 live 状态、trace 面板、分类/级别/时间过滤可用。
- AI 成功生成图层、取消后输入恢复、错误 `role=alert`、超时文案映射可用。

**结论：** 持久化、同步、撤销不是短板；短板是“让用户看见这些能力发生了”。

## 8. 实施路线

### Wave 0 — 止血（约 1 天）

**目标：消除确定性丢笔画、文件污染、重名与监控矛盾。**

1. **UX-01** 无画布门禁：禁用画笔/选择、空状态遮罩、`path:created` guard。
2. **UX-02a** 删除 30 秒自动下载 effect。
3. **UX-03** 监控错误率/错误数口径拆分。
4. **UX-07** 图层命名改为最大 `Stroke N` + 1。
5. **UX-19 快项** `lang=zh-CN`、`Blank`/`vector`/`AI chat`/`Logs:`/`chats` 文案；默认名/图层名中文化与 daemon 契约同批确认。
6. **UX-10** 图层按钮命中区 ≥24×24（先做热区，不放大字形）。

**出口：** 无画布不产生路径；空闲 30 分钟 0 下载；重名消失；监控两数可复算；所有图层按钮 ≥24×24。

### Wave 1 — 信任与首次体验（约 2 天）

**目标：用户知道“我在哪、画有没有保存、怎么开始、怎么回来”。**

1. **UX-02b** 保存状态 + 失败保留笔画/重试 + 画布错误横幅。
2. **UX-04** 空状态主 CTA + AI 无画布禁用/说明。
3. **UX-05** 新建确认 + 单级返回旧画布。
4. **UX-08** 真实缩放 + 状态栏去重。
5. **UX-12** 删除恢复条。
6. **UX-11** 图层面板上限 + 独立滚动（为 UX-10/09 打底）。

**出口：** 断 daemon 画一笔不丢且可重试；首次进入有主 CTA；新建可返回；状态栏显示真实比例；删除有撤销条；8 层聊天区 ≥240px。

### Wave 2 — AI 与连接（约 2 天）

**目标：AI 等待可解释、成功有落地、失败可恢复、取消不误导指标。**

1. **UX-14** 计时/阶段/终态 + 消费 `layerCreated` + revision 守卫撤销。
2. **UX-15** 中文错误分类 + 重试 + 草稿恢复 + 空气泡处理。
3. **UX-16** 取消剔除成功率分母 + n<5 显示 `—`（协议小幅增量）。
4. **UX-17** 状态栏连接指示。
5. **UX-06** 画布重命名（先默认名/导出时间戳，再做 PATCH + inline edit）。

**出口：** 20 秒等待有秒数；成功有“已添加图层”；停 daemon 错误中文可重试；取消不降成功率；断线 3 秒内可见；导出文件名可区分。

### Wave 3 — 能力完善（约 2–3 天）

**目标：把已有数据能力 surface 出来，让画笔和图层真正可用。**

1. **UX-09** active 语义 + 图层键盘可达（与 UX-10 同批）。
2. **UX-13** 重命名 + 透明度 + 类型中文化（一次拖动=一个撤销步）。
3. **UX-20** 画笔颜色 + 四档粗细 + 预览。
4. **UX-18** 窄屏断点 + 侧栏抽屉 + 菜单换行（依赖 UX-11）。

**出口：** 点击图层有画布反馈；键盘可完成图层管理；改名/透明度可用；画笔不再只有 1.8px 黑线；390px 可完成核心流程。

### Wave 4 — 打磨收口（约 1–2 天）

1. **UX-21** 对比度/focus-visible/输入框 label/aria-live/toggle 语义。
2. **UX-22** 监控加载更多 + 暂停语义。
3. **UX-23** 导出反馈 + JSON 备份语义。
4. **UX-24** 草稿 sessionStorage + 持久化边界文案。
5. **UX-25** 控件一致性 + R1 审计。
6. **UX-26** 图层顺序标识/pending 反馈。

**出口：** 关键路径 AA 项通过；监控可分页；导出有反馈；视觉与文案收敛。

## 9. 需要确认的开放问题

1. **画布重命名**是否需要新增 `PATCH /paint/canvas/:id`？这是 spec 缺口，不改数据模型；若本轮不做后端，至少完成默认名 + 文件名时间戳。
2. **`activeLayerId` 的产品含义**：画布选中对象（AI 图层才有意义）还是未来绘制目标？本轮建议按“选中/定位”实现，不改画笔“一笔一图层”模型。
3. **删除交互**：直接删除 + 恢复条，还是行内二段确认？本轮建议前者；原生 confirm 可移除。
4. **监控取消口径**：取消是否完全剔除成功率分母？n<5 的阈值是否用 5？需要产品/工程确认。
5. **响应式承诺**：是否正式写入「桌面优先、窄屏 ≥360px 可用，完整移动端不在 Phase 1」？
6. **自动下载**是否存在未记录的需求？全仓无 ADR/票据依据；建议直接移除。
7. **保存失败保留笔画**：当前 catch 会 `remove(path)`；工程需确认改为“保留 + 标记未保存 + 重试”的可行性。若复现失败丢笔画，UX-02 保持 P0。
8. **默认画布名中文化**：daemon 默认值、`canvas.test.ts`、导出文件名、旧画布兼容性需一起改。
9. **画笔设置持久化**：本轮会话级是否足够？刷新回默认是否可接受？
10. **用户验证**：以上优先级基于现场与代码，没有用户访谈；建议下一步用 5 人任务测试验证“首次画一笔 / 刷新 / 导出 / 新建 / AI 生成”五个节点。

## 10. 建议的验收脚本（人工）

1. **首次进入：** 清空 localStorage → 打开 → 画布区有主 CTA、画笔 disabled；点击画布不产生路径、无网络请求。
2. **保存：** 新建 → 画 5 笔 → 空闲 30 分钟 → Downloads 0 个；状态栏显示已保存。
3. **失败：** 停 daemon → 画一笔 → 笔画仍可见/明确标未保存 + 中文错误 + 重试；恢复 daemon 后重试成功。
4. **新建/返回：** 画布 A 有内容 → 新建 → 确认 → 返回上一张 → A 完整。
5. **图层：** 8 层 → 删除中间层 → 再画 → 无重名；删除后有恢复条，点撤销恢复；聊天区 ≥240px；按钮 ≥24×24。
6. **AI 成功：** 发“画一个红色圆形” → 有计时/阶段 → 完成有“已添加图层” → 撤销可用且只撤该步。
7. **AI 取消：** 发送后 1.2 秒取消 → 显示已取消 → 监控不计入失败。
8. **AI 失败：** 停 daemon 发送 → 中文错误 + 重试 → 无空气泡、草稿按规则恢复。
9. **连接：** 两标签同画布 → B 画 → A 1.2 秒同步；停 daemon → 状态栏 3 秒内提示；恢复 → 自动刷新。
10. **窄屏：** 390×844 → 无横向滚动、画布 ≥340×190、可完成建/画/撤销/导出。
11. **监控：** 制造 1 个 ai-chat error + 0 HTTP 失败 → 页面不再出现“0.0% / 1 个错误”；0 请求显示 `—`。
12. **可访问性：** Tab 全程有焦点环；图层行可 ↑/↓ 选择；读屏输入框名称中文；流式回复不逐段朗读。
13. **对比度：** 脚本扫描非禁用文本 ≥4.5:1。

## 12. 一句话结论

PaintCodex 的 Phase 1 已经“能画、能存、能刷新、能导出”，但首次体验被三个假象拖累：**假画布、假 100%、假保存**。本轮不需要新模块，只需要把这三个信号改成真的，再把图层、画笔、AI 等待与连接状态补完整——产品就会从“能演示”变成“敢让用户用”。
