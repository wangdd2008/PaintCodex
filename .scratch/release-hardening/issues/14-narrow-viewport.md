# 14: 窄屏可用

**What to build:** 正式承诺「桌面优先、窄屏 ≥360px 可用」：三档断点、侧栏改覆盖式抽屉、画布保住最小可用宽度，390×844 下能走完建画布 → 画 → 撤销 → 导出。

**Blocked by:** 06 (面板独立滚动是抽屉的前提)

**Status:** ready-for-human

**Covers:** UX-18

**Size:** M

## Acceptance Criteria

- [ ] 承诺写入代码注释与 spec：桌面优先，窄屏 ≥360px 可用；完整移动端不做。
- [ ] `≤1100px`：侧栏 `clamp(260px, 24vw, 320px)`，工具条 48px。
- [ ] `≤860px`：侧栏改为覆盖式抽屉 `min(320px, 86vw)`；Esc 关闭且焦点返回触发元素；菜单允许换行；隐藏文档名。
- [ ] `≤560px`：抽屉接近全宽；导出进第二行；状态栏允许换行。
- [ ] 画布最小可用宽度 ≥280px。
- [ ] 390×844：`document.scrollWidth ≤ window.innerWidth`（无横向滚动）；画布可视区 ≥340×190。
- [ ] 768 / 1024 / 1264 三个宽度无溢出。
- [ ] 12 层时 AI 输入框仍可见。
- [ ] 390×844 下可完成：建画布 → 画一笔 → 撤销 → 导出 → 刷新内容保留。
- [ ] 不做触控手势、双指缩放、移动端专用工具栏。

## Notes

- 现状 390×844：body `scrollWidth` 440、画布 34×18、侧栏固定 300、菜单延伸到 x=424；`app.css` 一条 `@media` 都没有（只有 `monitor.css` 有 1100/640 两档）。
- 断点的具体取值需要视觉取舍（抽屉宽度、菜单换行点），因此标记为 `ready-for-human`。
