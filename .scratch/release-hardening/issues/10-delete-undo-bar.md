# 10: 删除恢复条与撤销守卫

**What to build:** 去掉原生 `confirm`，删除即时生效并在面板顶部给出 8 秒恢复条；撤销入口绑定 revision，避免撤掉用户意料之外的东西。

**Blocked by:** 02 (反馈面与撤销守卫), 06 (面板顶部位置)

**Status:** ready-for-agent

**Covers:** UX-12

**Size:** S

## Acceptance Criteria

- [ ] 不再出现原生 `window.confirm`。
- [ ] 删除后 1 次往返内该行消失，图层面板顶部出现恢复条「已删除「笔迹 4」· 撤销」，8 秒后自动消失。
- [ ] 点「撤销」后名称、可见性、内容、像素完全恢复（与删除前一致）。
- [ ] 连续删除只显示最近一条恢复条。
- [ ] revision 守卫：仅当 `currentRevision === 删除时的 revision` 时撤销可点；用户后续有任何操作则降级为「已删除「笔迹 4」· 已有后续操作」，不可点。
- [ ] 删除失败就地显示原因与重试；不出现「看起来删掉了但刷新又回来」。
- [ ] 工具栏的全局撤销仍可用，作为兜底。
- [ ] 自动化：删除 → 撤销 → 断言图层数量与像素回到删除前；删除 → 再画一笔 → 断言恢复条不可点。

## Notes

- 现状删除成功无任何反馈，工具栏撤销可恢复（实测 9→8→9）。
- 撤销是快照级（ADR-0003），所以「撤错对象」的真实风险是后续操作覆盖，不是撤销本身。
